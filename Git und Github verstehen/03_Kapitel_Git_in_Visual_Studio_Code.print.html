1 Kapitel 3: Git in Visual Studio Code bedienen

1.1 Lernziele

Du kannst:

  • die Git-Ansicht in Visual Studio Code finden
  • den Zusammenhang von add, stage und commit erklären
  • Änderungen gezielt speichern
  • passende Terminal-Befehle den Schritten in VS Code zuordnen

1.2 Wo findet man Git in Visual Studio Code?

Bevor du deinen ersten Commit erstellst, prüfe auf Schulcomputern am besten auch kurz, ob user.name und user.email gesetzt sind. Wenn sich die Rechner nach einem Neustart zurücksetzen, musst du git config oft erneut im Repository eingeben.

In Visual Studio Code gibt es links in der Seitenleiste den Bereich:

Quellcodeverwaltung / Source Control

Oft ist dort ein Symbol mit verzweigten Linien und kleinen Kreisen zu sehen.

In diesem Bereich siehst du:

  • geänderte Dateien
  • gestagte Dateien
  • ein Eingabefeld für Commit-Nachrichten
  • Schaltflächen zum Synchronisieren

1.3 Was bedeutet add oder stage?

In Git gehört add zum Schritt, bei dem Änderungen für den nächsten Commit vorgemerkt werden.

In Visual Studio Code heißt dieser Schritt meistens:

Stage

Das bedeutet:

  • git add in der Kommandozeile
  • Stage Changes in Visual Studio Code

Beides meint fast dasselbe:

Die Änderung wird für den nächsten Commit ausgewählt.

1.4 Typischer Ablauf in VS Code

1.4.1 1. Datei ändern

Du bearbeitest zum Beispiel eine Datei aus deinem Kursmaterial.

Danach erscheint die Datei in der Quellcodeverwaltung unter den Änderungen.

1.4.2 2. Änderungen stagen

Klicke auf das Plus-Symbol neben einer Datei.

Dann wird die Datei in den Bereich Staged Changes verschoben.

Das entspricht:

git add DATEINAME

Mit

git add .

fügst du alle Dateien zur Stage Area hinzu.

1.4.3 3. Commit-Nachricht schreiben

Schreibe kurz und klar, was du geändert hast.

Beispiele:

  • Startseite fuer Git und GitHub erstellt
  • Kapitel zu Pull und Push ergaenzt
  • Kursmaterial aktualisiert

1.4.4 4. Commit ausführen

Klicke auf Commit.

Das entspricht:

git commit -m "Meine Nachricht"

Ein Commit ist ein bewusst gesetzter Speicherpunkt in der Projektgeschichte.

1.5 Merkhilfe

Datei aendern -> stage/add -> Commit-Nachricht -> commit

1.6 Wann sollte man committen?

Gut ist ein Commit immer dann, wenn:

  • eine kleine Arbeitsphase abgeschlossen ist
  • eine Datei sinnvoll ergänzt wurde
  • ein Kapitel fertig überarbeitet wurde
  • du einen klaren Zwischenstand sichern willst

Weniger gut sind Commits wie:

  • test
  • neu
  • aenderung

1.7 Hinweis

Wenn du in Visual Studio Code arbeitest, kannst du zusätzlich das integrierte Terminal öffnen. So siehst du direkt, wie die Schaltflächen in VS Code zu Befehlen wie git add und git commit passen.
